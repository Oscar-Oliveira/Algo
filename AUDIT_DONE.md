## Fase 0 — Contenção crítica de segurança

- **AL-01 + AL-32** [SEGURANÇA · CRÍTICA/ALTA] `algo_lang/compilador/codegen.py:_gerar_afirmar`, `algo_lang/tools/flowchart.py:texto_expr`. RCE via `afirmar`: a condição (texto vindo de `texto_expr`, não escapado) era interpolada diretamente numa f-string do Python gerado — uma condição contendo `{__import__(...)...}` executava código arbitrário quando a asserção falhava. Corrigido substituindo a reconstrução por f-string por `repr()` sobre a mensagem já formatada (nunca reavaliado como código). `texto_expr` documentado com o contrato de segurança (nunca embutir sem `repr()`/escaping adequado ao contexto de destino); confirmado que os call-sites de `flowchart.py` (`no()`/`aresta()`) já escapavam corretamente para o contexto DOT (sem `shape=record`, logo chavetas são texto inerte). Testes: `tests/test_correcoes_auditoria.py::test_afirmar_com_chavetas_na_condicao_nao_executa_codigo`, `::test_flowchart_texto_expr_com_chavetas_produz_dot_seguro`.

- **ON-01** [SEGURANÇA · CRÍTICA] `online/executor.py:_validar_nome_ficheiro` (nova função, usada por `_escrever_ficheiros_e_analisar`). O `nome` de cada ficheiro do estudante (vindo do editor web) era usado diretamente em `os.path.join(pasta_estudante, nome)` sem validação — um nome como `../../outra_pasta/x.py` ou um caminho absoluto escrevia fora da pasta do estudante. Corrigido com whitelist (rejeita `/`, `\`, `.`/`..` vazios) + confirmação por `os.path.realpath`/`os.path.commonpath` de que o caminho final resolvido continua dentro de `pasta_estudante`. Testes: `online/tests/test_executor.py::test_nome_de_ficheiro_com_travessia_de_caminho_e_rejeitado`, `::test_nome_de_ficheiro_absoluto_e_rejeitado`, `::test_nome_de_ficheiro_com_separador_e_rejeitado`.

- **ON-02** [SEGURANÇA · CRÍTICA] `online/executor.py:_resolver_inclusoes`. `incluir` no código do estudante aceitava um caminho absoluto tal-e-qual (`os.path.isabs` saltava o `os.path.join` com a pasta do estudante) e não protegia contra `../` em caminhos relativos — leitura arbitrária de qualquer ficheiro do servidor. Corrigido confinando sempre a `pasta_base` via `os.path.realpath` + `os.path.commonpath` (mesma mensagem de erro "não encontrado" tanto para ficheiro inexistente como para fora da pasta, para não revelar a um atacante se o caminho existe fora do sandbox). `os.path.commonpath` protegido com `try/except ValueError` (caminhos em unidades diferentes no Windows). Testes: `online/tests/test_executor.py::test_incluir_caminho_absoluto_fora_da_pasta_e_rejeitado`, `::test_incluir_travessia_de_caminho_fora_da_pasta_e_rejeitado`.

- **AG-27** [SEGURANÇA · CRÍTICA] `alguem/nucleo/ficheiros_visiveis.py:resolver_ficheiros_visiveis`. Mesma classe de defeito que ON-02: `incluir` no código do estudante (detetado por regex, não pelo parser real, propositadamente tolerante a erro de sintaxe) abria qualquer caminho absoluto ou com `../` sem confinamento — leitura arbitrária de ficheiros do servidor, visível ao LLM e por extensão à resposta mostrada ao estudante. Corrigido confinando à pasta do ficheiro principal (o exercício) via `os.path.realpath` + `os.path.commonpath`, mesmo padrão do ON-02. Testes: `alguem/tests/test_ficheiros_visiveis.py::test_incluir_caminho_absoluto_fora_da_pasta_e_ignorado`, `::test_incluir_travessia_de_caminho_fora_da_pasta_e_ignorado`.

- **ON-14** [SEGURANÇA · CRÍTICA] `online/credenciais.py:_validar_host_ollama`, chamada por `guardar_credencial`. O campo `host` da credencial Ollama (escolhido pelo estudante) é usado pelo `alguem/fornecedores/ollama.py` como URL base de um pedido HTTP feito pelo **servidor** — sem validação, um host como `http://169.254.169.254` (metadata de cloud) ou `http://127.0.0.1:<porta interna>` é um SSRF clássico contra o próprio servidor/rede interna. Corrigido validando o esquema (só `http`/`https`) e resolvendo o hostname por DNS (`socket.getaddrinfo`), rejeitando qualquer endereço privado/loopback/link-local/reservado/multicast (`ipaddress`). Um teste pré-existente (`test_guardar_credencial_substitui_a_anterior`) usava `http://localhost:11434` como valor de exemplo incidental — atualizado para um IP público literal (`8.8.8.8`, não requer DNS real em teste) já que a correção passa a rejeitar loopback deliberadamente. Testes: `online/tests/test_autenticacao_e_credenciais.py::test_credencial_ollama_com_host_interno_e_rejeitada` (parametrizado: loopback por IP/nome, link-local/metadata, rede privada), `::test_credencial_ollama_com_esquema_invalido_e_rejeitada`, `::test_credencial_ollama_com_host_publico_e_aceite`.

- **ON-05** [SEGURANÇA · CRÍTICA] `online/executor.py:_env_minimo`, usada por `ExecucaoInterativa.iniciar`. O subprocesso que corre o programa do estudante herdava todas as variáveis de ambiente do servidor (`asyncio.create_subprocess_exec` sem `env=`), incluindo `ONLINE_CHAVE_CIFRAGEM`/`ONLINE_CHAVE_SESSAO`. Corrigido passando um `env=` explícito com só o mínimo necessário (`PATH`, mais `SYSTEMROOT`/`SYSTEMDRIVE`/`TEMP`/`TMP` em Windows, para desenvolvimento local — produção corre sempre em Linux). Teste: `online/tests/test_executor.py::test_subprocesso_nao_herda_variaveis_de_ambiente_do_servidor`.
